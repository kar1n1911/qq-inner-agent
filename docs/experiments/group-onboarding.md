# 实验线路：群聊引入与活跃性机器人

**分支**：`experiment/group-onboarding`
**状态**：**休眠，仅保留计划**。本分支是**话题系统的细分分支**：在话题系统之上增加简历与新人引入；话题的选择与投递仍由话题系统负责。
**目标**：按三个阶段搭建并验证——二人群观察期 → 简历摄入 → 新人加入（引入 + 话题池 + 适用范围），再决定哪些结论回灌 `main`。

## 与话题系统的关系

**这是话题系统的一个细分分支，不是并行的第二条路线。**

| 层 | 内容 | 归属 |
| --- | --- | --- |
| 话题系统 | 三层生命周期、按群反馈学习、身份/归属、生成与选择闸门、拉取与推送（§2.20 / §2.24） | 主线，先在 `main` 上统一完成 |
| 本分支（细分） | 在话题系统之上增加**简历驱动的候选**与**新人引入** | 从话题系统的分支上切出 |

因此：

1. **`main` 保持统一**，先把话题系统做完；
2. 开始做话题系统时从 `main` 拉话题分支；
3. 本分支从**话题分支**切出，而不是从 `main` 另起一套；
4. 本分支**不实现**第二套话题池、冷场判定或投递闸门——这些都复用话题系统，
   本分支只增加"来源（简历）"与"引入行为"。

**反例（禁止）**：在实验分支里另造话题池与冷场口径，与话题系统并行发展。
那会形成两套"什么算合适话题"的判断，线上行为无法比较。

## 为什么单独开分支

这不是主线功能，而是**实验环境搭建**，有三类东西不适合直接进 `main`：

1. **数据结构变更**：话题池需要新表或新字段，`main` 的 schema 迁移必须单独评审；
2. **实验配置**：实验群、简历数据、冷场阈值、检索频率都只在该环境成立；
3. **未定策略**：引入话术、适用域标注、置信标准仍在讨论，不能当作稳定行为发布。

`main` 只保留 `TODO.md` 的指针，不承载实验代码，直到结论稳定。

## 环境搭建清单

### 0. 实验环境是独立实例

实验环境**不是当前环境的配置项**，而是一套独立实例：

| 维度 | 当前环境（`main`） | 实验环境（本分支） |
| --- | --- | --- |
| 运行根 | 现有部署根（`config.json` + `data/`） | 独立 `--root`，例如 `~/lab/group-onboarding` |
| 配置 | 主线 `config.json` | 自己的 `config.json`（实验群、阈值、频率） |
| 数据 | 现有 SQLite 与日志 | 独立 `data/`、`.runtime/`、日志 |
| 群 | 现有群（含两人测试群） | **真实存在的 ≥3 人群**（需另建或另选） |
| 简历 | 不存在 | 三份 `profiles/<qq>.json` |
| 账号 | 现有 OneBot 账号 | 可复用同一协议端，但群与数据分离 |

由此得到三条硬约束：

- **不修改主线 `config.json`**，也不往主线的 `allowedGroups` 追加实验群；
- `agent.topicLifecycle` 在**实验实例的配置**里开启，与主线无关；
- 实验群必须是**真实可用**的 ≥3 人群；如果不存在，先建群——这是用户侧动作，不是配置项。

### 1. 实验实例的运行配置

| 项 | 值 |
| --- | --- |
| 根目录 | `~/lab/group-onboarding`（独立 `--root`） |
| 实验群 | ≥3 人、真实可用，写入**实验实例**的 `config.json` |
| 话题学习 | 实验配置里显式开启 `agent.topicLifecycle` |
| 冷场阈值 | 可配，默认 15 分钟无人类消息 |
| 检索频率 | 可配，默认 6 小时，失败保留旧池 |

以上全部只存在于实验实例，主线的 `config.json` 一行不改。

### 1.1 三个阶段与准入条件

机器人先进一个**二人群**，观察真实的聊天行为、语气与内容；之后才到简历与新人。

| 阶段 | 场景 | 目标 | 准入条件 |
| --- | --- | --- | --- |
| **0 观察期** | 机器人加入二人群，**按自身人格正常运行**（自动接话、主动提话题），同时记录两人的聊天行为、语气与内容 | 在不停行为的前提下积累样本 | 群存在且机器人已加入；实验配置里 `learning.enabled`、`expression.learn`、`observation.enabled` 为真 |
| **1 简历摄入** | 拿到两份简历（Word / PDF 等） | 抽取文本与特点，形成可用的背景依据 | 简历文件与**本人授权**；抽取失败可见 |
| **2 新人加入** | 第三人入群 | 介绍另外两人；冷场时从话题池取话题 | 阶段 0 有足够样本；话题池非空；适用域可判断 |

**实验期不改变机器人的日常行为。** 自动接话、主动提话题、按人格发言都照常运行；
观察是**并行记录**，不是静音模式，也不是"先观察后上线"的两段式。

由此有三条具体约束：

- 新增能力是**叠加**：话题池、简历背景、冷场触发都接在现有投递闸门之后，不替换原有行为；
- 如果为了收集证据而改变行为（例如关掉主动发言），那收集到的样本就不再代表真实表现，验收无效；
- 阶段 0 的验收**不是**"学成了语气"——`expression` 学习当前仍属待观察项（TODO 2.12）。
  验收是**原始证据可查**：消息量、群观察记录、表达候选，且能说清"哪些证据来自哪个群"。

**唯一的例外是安全阈值**：如果现有行为在二人群里已经产生过度侵入（例如反复提已结束的话题），
应当按既有闸门修正，而不是为了"保持行为一致"放任——实验记录必须同时注明当时的行为配置。

### 1.2 推送通道与数据源（2026-10-18 已配置）

#### ntfy（lab 实例）

| 项 | 值 |
| --- | --- |
| 运行方式 | systemd **用户**服务 `ntfy-lab.service`（`systemctl --user`，不碰系统级） |
| 监听 | `127.0.0.1:2586`（仅本机） |
| 鉴权 | `auth-default-access: deny-all`，admin 用户 + Bearer token |
| 缓存 | 12 小时，支持 `?since=<id>` 断线续传 |
| 凭据 | `~/lab/ntfy/credentials.txt`（权限 600）。**topic / token / 密码都不写进本文件，也不入仓库** |
| 验证 | 匿名发布返回 403；带 token 发布 200；订阅返回 `event=message` 的 JSON |

订阅方式（机器人侧）：

```text
GET http://127.0.0.1:2586/<topic>/json?since=<last-id>
Authorization: Bearer <token>
```

只处理 `event == "message"`；`open` / `keepalive` / `message_delete` 忽略。

部署踩过的两个坑，记下来避免重复：

- Docker 需要 docker 组权限，当前用户没有，因此改用官方静态二进制；
- `pkill -f "ntfy serve"` 会匹配执行它的 shell 自身，连会话一起杀掉；停服务请用 `systemctl --user stop`。

#### 数据源（实测，2026-10-18）

**拉取侧**

| 源 | 状态 | 备注 |
| --- | --- | --- |
| GitHub API / Search | 200 | 未认证 **60 次/小时**；加 token 提到 5000/小时 |
| Hacker News（Algolia API） | 200 | JSON，无需鉴权 |
| arXiv API | 200 | Atom，适合论文类话题 |
| Lobsters / Ars Technica / Product Hunt | 200 | 标准 RSS/Atom |
| 36kr / 少数派 / V2EX | 200 | 中文源，RSS |
| 阮一峰周刊 | 200 | Atom |
| Bilibili 热门 API | 200 | JSON，偶尔需要 UA/Referer |
| BBC News | 200 | 通用新闻 RSS |

**不可用 / 需中转**

| 源 | 状态 | 处理 |
| --- | --- | --- |
| Reddit JSON | 403 | 需要 OAuth 或 RSSHub |
| 知乎 | 403 | 需要登录态或 RSSHub，不建议硬抓 |
| Solidot RSS | 000 | 不可达，放弃或换镜像 |

**推送侧**：任何能发 HTTP 的实体都可以推（自建脚本、推荐服务、n8n/IFTTT/Zapier、其他 bot）。
知道 topic 与 token 才推得进来。

#### 实现前的限制

1. **GitHub 未认证 60/小时**，定时抓取容易打满；实现时 token 放配置存储；
2. **RSS 解析需要新增依赖**（`feed-rs` 或 `quick-xml`），属新增依赖，需单独评审；
3. **被拦的源不要硬抓**，走 RSSHub 或官方 API；
4. ntfy 的 topic 与 token 都是凭据：当前只绑回环；实验机若在别的机器，绑 Tailscale 地址或前置 TLS。

### 1.3 部署拓扑：全部在同一台 VM（用户 2026-10-18 决定）

实验实例与现有部署**同机共存**，因此有三条硬约束：

| 约束 | 内容 |
| --- | --- |
| 路径隔离 | 实验实例用独立 `--root`（`~/lab/group-onboarding`），自己的 `storage.directory`、控制套接字与 `.runtime`，不得指向生产的 `data/` |
| 白名单必须互斥 | 两实例连**同一个 NapCat**（`ws://127.0.0.1:3001`），都会收到全部事件；隔离只靠 `allowedGroups`。**实验群不得出现在生产 `allowedGroups` 里，生产群也不得出现在实验配置里**，否则同一句话会被两个实例各回一次 |
| 端口不冲突 | 生产占用 `5097`/`5098`/`39337`（dashboard）与 `3000`/`3001`（NapCat），ntfy 占 `2586`。实验实例默认**不启动 dashboard**，只看 `status.json` 与控制套接字；若确需 dashboard，另分配端口 |

ntfy 只绑回环即可：机器人都在这台 VM 上，不需要对外暴露，也不需要 TLS。

实验实例启动方式（待群和账号确定后填配置）：

```bash
qq-inner-core --root ~/lab/group-onboarding start
```

### 1.4 回放语料：LCCC（2026-10-18）

用户决定：**不必等真实群**，先用公开中文对话语料做回放，把话题选择与冷场判定跑起来。

| 项 | 内容 |
| --- | --- |
| 语料 | LCCC（thu-coai，MIT），取 **test 分片**：10,000 段对话，gzip 537 KB |
| 直链 | `https://huggingface.co/datasets/silver/lccc/resolve/main/lccc_base_test.jsonl.gz`（`thu-coai/lccc` 仓库本身只有加载脚本，数据在 `silver/lccc`） |
| 原始格式 | 每行一个 JSON 数组，元素是**空格分词**的句子；**没有发言人、没有时间戳** |
| 预处理 | `scripts/lab/lccc_replay_prep.py`：去空格拼回自然中文（ASCII 词之间保留空格），按轮次轮流赋 `member-a/b`，固定 25 秒间隔，跳过 <2 轮或超长句 |
| 样本 | `~/lab/group-onboarding/corpus/replay_sample.jsonl`（200 段，可复现） |

**这些补齐是模拟器假设，不是数据事实**：LCCC 不含发言人身份与时间，交替说话和固定间隔都是脚本编的，
读结果时必须带上这条前提，否则会把模拟行为当成真实群行为。

**它不能替代什么**：

- 不能证明"这两个真实的人会怎么反应"（语气、关系、群规都来自真实群）；
- 不能验证"惠及三人"（语料是两人短对话，没有群结构）；
- 不能验证冷场的真实阈值（固定 25 秒间隔不是真实沉默分布）。

用途限定：**受控输入下的行为一致性**——同一段回放，话题选择/冷场/引入的判定是否按预期工作。

### 2. 简历摄入（Word / PDF / 纯文本，不假设 JSON）

**输入不预设格式**。实际会拿到 `.docx`、`.pdf`，也可能有 `.doc`、`.txt`、`.md`。

| 格式 | 抽取方式 | 失败时 |
| --- | --- | --- |
| `.pdf` | `pdftotext`（VM 已装） | 明确报错；扫描件走 OCR 或要求提供文本版 |
| `.docx` | `unzip -p <file> word/document.xml` + 去标签 | 报错并保留原文件名 |
| `.txt` / `.md` | 直接读取 | 编码不是 UTF-8 时报错，不做猜测 |
| `.doc` | 无 LibreOffice，**明确不支持** | 提示先转成 `.docx` 或 `.pdf` |

抽取脚本放在实验分支的 `scripts/`，逐文件记录结果：成功、失败原因、字符数。

**产出是两步，不是一步**：

```text
data/profiles/<name>/
  source.docx|pdf      ← 原件，gitignore，不进日志、不进备份
  extracted.txt        ← 抽取的纯文本
  profile.generated.json ← 由我们生成的结构化摘要（不是输入格式）
```

`profile.generated.json` 是**产物**，字段由我们定：

```json
{
  "qq": null,
  "display_name": "…",
  "interests": ["…"],
  "role": "…",
  "notes": "…",
  "source_file": "source.pdf",
  "consent": { "scope": "experiment", "confirmed": true }
}
```

- `consent` 缺失的人**不参与**介绍与话题筛选；
- 简历只用于筛选与总结，不进入发言正文；
- 原件与抽取文本都在 `.gitignore` 内。

## 能力与最小验收

### A 新人引入

- 输入：三人简历；
- 输出：把另外两人介绍给新人（必要时反向）；
- 验收：同一输入可复现；介绍不含简历原文；`consent` 缺失的人不出现在介绍里。

### B 话题池（消费方，不另造池子）

- 输入：三人兴趣标签 + 群上下文；**池子的生产与淘汰沿用话题系统的结论**，本分支只负责取用与过滤；
- 处理：联网检索 → 去重 → 打分 → 入池；过期与低分淘汰；
- 验收：冷场触发时能取到一条通过适用域过滤的话题；池空时状态可查；抓取失败保留旧池。

### C 适用范围

- 每个话题带 `scope`：适用群、适用人群、适用场景（破冰/冷场/接话）、时效；
- 验收：不满足 scope 的候选**不发出**；过滤结果可在状态里看到。

## 不合并策略

实验结论稳定后，按以下顺序回灌 `main`，每一小步都可回滚：

1. 只回灌**观测与状态**字段（零行为变更）；
2. 回灌**话题池读写**（不带检索）；
3. 回灌**检索与淘汰**；
4. 最后才回灌**发言策略**（引入话术、冷场触发）。

schema 变更单独评审，不与行为改动同一个提交。

## 风险

- **隐私**：简历是个人信息，来源、用途、公开范围必须单独授权；不得默认披露到群；
- **背书**：机器人读过简历不等于真人认识，不得模拟熟人背书；
- **验证环境**：两人群无法验证"惠及三人"，实验群必须是 ≥3 人；
- **实验漂移**：分支长期不合会与 `main` 分叉，需定期 rebase 并记录差异。
