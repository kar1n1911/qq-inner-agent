# P5b 群内装饰素材:采集与索引

你是 qq-inner-agent 的工程师。

## 定位:新功能,**只做 Rust**

后端已确定转向 Rust,因此**尚未实现的设计只做 Rust,不再补 JS 实现**。

本阶段是**全新功能**,JS 里没有对应物,所以:

- **不受 parity 约束**(没有 JS 参照可对照),但也因此**没有交叉验证兜底**;
- 验证靠**行为测试与设计符合性测试** —— 必须把设计文档里写的规则**逐条变成断言**
  (例如"同一张图只落一份"、"下载失败不写记录"、"模糊输入返回 `confident: false`");
- 凡是能确定性推导的期望值,**不要从实现里反推**,要从设计规则手算出来写进测试。

⚠️ **如果本阶段需要改动某个已经迁移完成的模块的既有行为**(例如 `store` 的写库路径),
必须把新行为做成**可开关且默认关闭**,让默认路径与 JS 逐字一致 ——
否则既有的 parity 测试会失败,等于顺手砍掉安全网。

## 任务

### 1. 采集(JS 与 Rust 都要)

在入站**人类消息**里识别装饰段:`image` 与 `face`(内置表情 id)。

- **只采人类发的**,不采 agent 自己发过的(**这是硬要求**:否则会自己学自己,形成自我强化);
- **必须当场把字节落盘** —— OneBot 给的 `file` 字段多为**带过期的临时 URL**,只存 URL 几天后就是死链。
  - 若 `file` 是本地路径 → 直接拷贝;
  - 若是 URL → 立即下载;
  - 若该实现提供"取文件"接口 → 优先用它;
  - 下载失败 → **记录失败并跳过**,绝不写半条记录。
- 落盘位置:`<dataDir>/media/<chat>/<sha256>.<ext>`(目录 0700);
- **按哈希去重**:同一张图被用 50 次 → **一条素材记录 + 使用次数 50**,而不是 50 个文件。

### 2. 索引表

新增 `media_assets`(直接用 `scripts/` 或现有迁移方式建表,**不要改已有表**):

| 列 | 说明 |
| --- | --- |
| `chat` | 群/私聊(键空间与现有一致) |
| `hash` | sha256,`(chat, hash)` 唯一 |
| `kind` | `image` / `face` |
| `file` | 相对路径,或 `face` 的 id |
| `occurrences` | 被使用次数 |
| `first_seen` / `last_seen` | 秒 |
| `bytes` | 文件字节数 |
| `fitness` | **按场合分桶的适配度**,见下(初始为 `{}`) |

**上下文只存引用,不要复制正文**:另建 `media_contexts(chat, hash, message_id, role)` 记录"这次使用发生在哪条消息附近",正文从 `messages` 表按 id 取。这样不会重复存储,也不会出现两处正文不一致。

### 3. 交流阶段分类(共享基础件)

`docs/prompt-and-learning-design.md` 第十一节定义了**两轴**:生命周期(展开中/收束/自然终止/单发)× 与上文关系(接续/转向/无关单发)。

本阶段只做**纯函数 + 记录**,不做任何学习:

- 输入:一段消息(可用 id 列表)+ 配置;
- 输出:`{ stage, relation, confident: bool }`;
- **全部用结构量**:相邻消息相似度(复用现有分词)、来回次数、时间断口、收束标记集(**放配置**,不写死);
- **不确定时必须返回 `confident: false`** —— 本阶段只是记录,后续阶段会**依据它决定是否产生学习信号**。

## 硬性约束

1. **不得引入新依赖**(JS 侧只用内置模块;Rust 侧沿用现有依赖)。
2. Rust 侧不得改动既有 parity 测试的语义;若必然影响,先说明。
3. 中文注释,重点标注:**URL 过期所以必须当场落盘**、哈希去重的理由、
   "只采人类"的理由、以及"不确定要如实返回 `confident: false`"。

## 验收标准

1. JS:`node --test test/*.test.mjs` 全过(允许既有的 macOS 平台失败);
   Rust:`cargo build --release`、`cargo clippy --all-targets -- -D warnings`、`cargo test` 全过。
2. 测试覆盖(两边都要):
   - 同一张图多次出现 → **只有一条记录、`occurrences` 递增、只有一个文件**;
   - URL 下载失败 → **不写入任何记录**;
   - 自己发的图**不被采集**;
   - `face` 与 `image` 都能入库且能区分;
   - 分类器:展开中/收束/自然终止/单发 各至少一例;**模糊输入返回 `confident: false`**;
   - **不访问真实网络**:下载用本地 mock 服务端。
3. 不读取真实 `secrets.json`,不写真实 `data/`。

2. 用一段话回报:实现了什么、测试怎么跑、URL 过期与去重怎么验证的、与设计的偏差或不确定点。
