## 2. 入口、“三条线路”与汇合

**调用入口**有三类，但不等于三条发言触发线路：

1. 实时 OneBot 事件：`main.rs:437-488` 先通知控制端；默认路径先 `policy::resolve_forwards` 再 `Engine::ingest`，可选 `QQ_INNER_ONEBOT_IO=1` 经 OneBotAdapter 映射为 `Incoming` 再 `ingest_incoming`。二者写同一个会话状态：去重入库、感知，活动窗口内设置 `pending/version/hint/due=now+debounce`，**入站本身不启动文本 cycle**。`mod.rs:491-570,607-766`。
2. 每秒时钟：`main.rs:725,734-737` 调 `Engine::tick`。它先刷新身份/观察资料，检查参与状态、活动块、在线、配置、并发、活跃窗口、`due` 与最小思考间隔，再为每聊天选触发器，设置 `busy` 和版本快照，启动文本 `cycle` 或 `media_cycle`。`mod.rs:912-997,1145-1255`。
3. 历史回填：连接/重连及间隔到期由 `main.rs:415-430,439-445,734-737` 调 `backfill_once`；拉允许群历史，走 `ingest_backfill`。它可入库、观察、学习、采集素材，但 `backfill` 不创建活跃 `ChatState`，也不设 `pending` 或调用 `cycle`。`mod.rs:603-605,710-749`。它只在持久化数据层与后续实时思考汇合。

**代码中的“三层”确切含义**见 `decision.rs:1,47-120`：①由 `pending` 驱动的**消息回复资格**，②由群状态/想法池/已处理边界驱动的**主动话题资格**，③共用的**候选形成→评价→选择→预测→表达/发送**流水线。启用 `agent.threeLayerDecision`（当前 `config.json:189` 为 `true`）时，①②各自计算阻断原因，回复优先；若回复获准，同时保留一次有期限的主动话题考虑，之后才有机会走②。两者在 `tick` 汇合到同一个 `cycle(chat, trigger, start)`；③不是第三个独立触发源。`mod.rs:1168-1200,1234-1241,1444`。话题抽签只在②获准后进行，输掉也消耗本次考虑。`mod.rs:1189-1197`。

另有**独立媒体支线**：关闭三层开关时，非 `pending` 的群可选 `trigger="media"`，转入 `media_cycle`，不进入文本③；媒体选择使用群活动、语料与抽签，并走同一 `busy`/观察/活动/总配额/投递账本约束。`mod.rs:1201-1209,1234-1241,803-910`。关闭三层开关且无媒体触发时，还可在 `pauseSeconds` 后由 `trigger="pause"` 进入共同文本 cycle。`mod.rs:1201-1209`。因此若把“三条线路”理解成“三条相互独立的发言触发路径”，**代码不支持固定数目三**；其数量随开关变化。历史回填不是发言线路。

## 3. 从消息到发言：真实顺序

以下为当前 `threeLayerDecision=true` 的普通文本路径；括号内为条件分支。

1. **接入/感知**：OneBot 转发展开；归一化过滤非消息、自己/忽略用户、目标/白名单、无有效服务端时间、空正文，并判私聊/点名/他人/open `hint`；主人命令先去重并单独排队。普通消息先限制活动聊天数、去重入库并分配 `message_key`，再 OCR/表情频率/素材采集、观察计数、短期记忆 capture；只有实时且活动窗口内的消息更新 expectation 与 `pending/version/last_human/last_id/hint/addressed_id/due`。`main.rs:473-483`；`policy.rs:723-883`；`mod.rs:613-766`。P2 中立入口目前拒绝媒体段和命令，感知能力少于默认入口。`mod.rs:496-570`。
2. **tick 初筛**：参与状态、活动块（直接点名/私聊可叫醒）、在线/模型 readiness、最大并发、`busy`、窗口、debounce、最小思考间隔；①②分别查静默、总配额，②额外查主动开关/配额/冷却、仅群、想法池或外部来源、群作息/安静时间、期望、已处理消息，再计算话题概率。①优先，②在无①时抽签；静默复核，锁内占并发名额并捕获版本。`mod.rs:971-995,1145-1233`；`decision.rs:38-145`。
3. **cycle 入口**：再次查参与/白名单/活动、版本和①/②资格；`orientation.before_speak`（必要时采集、等待、分析）及身份刷新；等待后再验版本与活动，捕获活动块、观察 epoch、学习 epoch 等失效凭证；非 topic 且已有发送 assessment 时不重入。`mod.rs:1444-1538`；`orientation.rs:306-358`。
4. **上下文与早期配额**：读历史（默认补全最后一次自身发言后的全部未读；简读开时仅对 message 模型输入采样）、最后人类消息、小时总/主动配额及主动冷却（情绪 burst 可豁免）；确定学习条件、最近三条 query，拼人设/身份、记忆、表达、想法池、expectation、观察与积压摘要。主动话题可在群活动资格后抓取外部话题/relay，并先审核再注入 FORMATION。`mod.rs:1539-1759`；`backlog.rs:57-151`。
5. **形成与学习**：FORMATION 产出 allocation/candidates；可按单轮预算 recall 后重做 FORMATION；校验结果、freshness、应用情绪；可选学习自审与落库、刷新上下文；最多接收前三个有效新候选并存入 `thoughts`，再从未使用且未过期的想法池取候选。`mod.rs:1761-1948`。
6. **评价与选择**：EVALUATION → 严格过滤评分、回写想法分数 → fresh 检查；显式点名覆盖 allocation，按沉默补偿、相关度/原创度/动机及 system1 兜底只选一个候选并抽一次签；主动开关/静默复核，不通过则 withhold、`finish`。`mod.rs:1949-2016`；`policy.rs:245-324`。
7. **发送概率（配置启用时）**：读取发送间隔、近一分钟人类数；FORECAST 校验 → 六因子乘积及预测 veto、情绪修正 → 随机抽签 → **先写 `send_assessments`**；未获准便记录决策、`finish`，不调用 ARTICULATION。未启用则跳过此层。`mod.rs:2001-2081`；`sending.rs:69-120,184-245,255`。
8. **表达与最后闸门**：先抽长度档位，再确定装饰、纯表情、多气泡资格与 backstory；ARTICULATION 后验证正文/气泡、禁用思维标签、情绪内容及来源标注；复核版本/epoch/活动窗口、在线、静默、重复；`decision::topic_delivery` 以所选思想及回复目标分近期/结束/遥远，旧话题需明确可引用对象、结束状态，遥远话题还需必要性；再查 dry-run。`mod.rs:2082-2311`；`decision.rs:150-293`。
9. **选择目标、记账和投递**：校验 `replyTo`/提及，旧话题强制精确引用；先建 `deliveries=pending`、标记思想已用及 handled；每条气泡先延迟，再复核失效/活动/静默/在线/配额，后续气泡逐条预留 delivery。发送走 `send_chat`（P2 会话用 `ChatPort`，否则 `EngineTransport`）；收到 ACK 才记自身消息和投递结果、表达使用、expectation、decision。失败或不确定只记账，不自动重发。`mod.rs:2312-2529`；`targeting.rs:14`；`store/operations.rs:25-31,212-235`。

所有网络/模型等待后需要检查 `fresh/obsolete`，其依据含 stop/离岗、聊天版本、活动块、学习 epoch、观察 epoch；模型 future 可取消，已启动的阻塞请求仍可能继续消耗预算。`mod.rs:1336-1363`。文本③与媒体支线不是同一发送判断链，教学确认与身份外显也不经③。`mod.rs:997-1143,803-910`。

## 5. X4：自然接缝与顺序

**候选插件接缝**（需要将现有硬编码调用抽成契约，当前尚非插件）：

| 接缝 | 可换的行为 | 必须保留的输入/输出契约 |
|---|---|---|
| 入站归一化/感知 | 协议适配、媒体/OCR、观察、短期记忆 capture | 每条证据稳定的 `message_key`、去重、服务端/接收时间、来源与账号范围；见 `mod.rs:496-570,607-766`。 |
| 触发资格与调度 | ①回复、②主动话题、旧 pause、媒体或新增触发器 | 返回阻断原因/概率、触发意图、活动窗口和失效版本；共享 chat 单飞与全局并发名额。`decision.rs:8-120`；`mod.rs:1145-1241`。 |
| 上下文提供者 | 记忆、人格、观察、外部话题、积压摘要 | 每个片段标明可信度/来源/预算，异步返回后验证 turn freshness；外部条目先审核。`mod.rs:1383-1443,1539-1759`。 |
| 候选/评价/选择 | FORMATION、EVALUATION、想法池、参与抽签 | 候选 ID、评分校验、使用/过期状态、单次抽签；`mod.rs:1761-2016`。 |
| 发送准入 | 配额、静默、预测、情绪、话题分层、重复 | 区分回复与主动发起，返回可审计理由；最终投递前仍复核时效/版本。`mod.rs:1558-1571,2017-2081,2244-2311`。 |
| 表达/目标/投递 | 长度、多气泡、引用与提及、传输端口 | 先验允许的输出能力、每片段验证及 delivery 账本/ACK 语义。`mod.rs:2082-2529`；`targeting.rs:14`；`io/ports.rs:8-13`。 |

**语义必需的先后/偏序**（重排时仍需成立）：

1. 准入过滤与去重成功 **先于** capture/观察计数/pending：否则重放消息制造记忆、活跃状态和重复答复。命令也须先去重，再执行。`mod.rs:653-705,719-766`。
2. 实时消息设置 `version/due` **先于** tick 捕获版本并置 `busy`；异步步骤后检查版本/epoch/活动块 **先于**提交学习、继续决策或发出气泡，否则旧思考覆盖新消息/新入群/重置。`mod.rs:750-765,1219-1232,1351-1363,1798-1808,1880-1884,2361-2377`。
3. ①回复与②话题要分别判资格，但**未处理回复优先**；②不得凭未回答消息发起新话题，也不能把回复计入主动冷却/配额。`decision.rs:47-120`；`mod.rs:1182-1200`。积压简读只改模型输入，不可改完整证据、学习/发送语义。`mod.rs:1540-1596`。
4. 观察满足/生成资料 **先于**发言；不可信外部条目安全审核 **先于**进入形成模型。`orientation.rs:306-358`；`mod.rs:1658-1686`。
5. 候选形成 **先于**评价，评分/选择 **先于**FORECAST；发送 assessment/抽签 **先于**ARTICULATION，且 assessment 持久化后才能生成，防止同消息重入。`mod.rs:1761-1797,1922-2081,1526-1529`。
6. ARTICULATION **先于**正文/气泡安全验证、重复检查、话题层级与目标校验；话题层级需要已选候选、实际回复和可引用历史，不能只凭候选创建时间。`mod.rs:2175-2333`；`decision.rs:175-293`。
7. `deliveries=pending` **先于**网络发送；收到 ACK 后才写成功状态和自身消息；各气泡延迟后的复核 **先于**该片段发送；不确定送达不重放。`mod.rs:2334-2529`；`store/operations.rs:25-31,212-235`。
8. 同 chat `busy` 与并发名额在同锁中占用；Core→Store 锁序和不跨网络 `await` 持这两个锁，是当前并发正确性约束。`mod.rs:1-2,1219-1254,1476-1490,1809-1810`。

**仅当前实现的顺序，可在满足上述依赖后重排/并行**：tick 中身份刷新、观察资料采集、教学/身份任务与普通聊天扫描的相对先后（各自有单飞和参与守卫）；记忆/表达/身份等只读上下文片段的装配次序；外部 feed 与 relay 两种来源的收集次序（各自仍先审核）；候选评分后的非依赖性日志；不同聊天间的调度次序**在明确重新定义公平性时**可改。`mod.rs:918-1148,1383-1428,1616-1738,1949-1965`。当前 `Core.chats` 保留插入顺序，直接更改会影响有限并发名额分配，所以这属于可改策略，不是无影响交换。`mod.rs:207-240,1149-1154`。浮点发送因子的乘法顺序若要求逐值兼容须保持原顺序。`sending.rs:1-5,230-240`。
