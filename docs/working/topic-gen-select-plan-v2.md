# 话题生成与选择专项规划 v2（2026-10-17，只读规划）

依据：完整阅读 `docs/working/topic-literature.md`（35 项、§A–F），核对代码；另核对 #4 原论文全文（https://arxiv.org/html/2501.00383）、#27/#28 期刊摘要、#23 作者提供的摘要、#26 出版社摘要及 #1/#3 原研究页面。#24/#25 正文仍未取得，不推断其实验效果。`/tmp/topic-gen-select-plan.md` 不存在，故以此前会话给出的上轮规划与当前代码为比较基线。未修改仓库、未跑测试。

## 一、现状及与文献的对应

1. #4 的目标是 trigger → retrieval → thought formation → evaluation → participation。旧想法可保留并在新语境重评；每个想法标注来源刺激，并评价“现在表达的动机”，可以等待。我们的 FORM 有 system1/system2、历史与记忆、每次至多 3 个候选；`thoughts` 按群、used=0、创建 1800 秒内取最多 12 个，再评价。区别：仅文本/类型/创建时间/subject，无可核验来源或话题归属；等价文本才去重；无想法且未启外部来源时，`screen` 阻止主动 FORM，不能称持续独立的想法流；留存 1800 秒是存活期而非“语境变合适”条件；最终话题闸门拒绝时会将该候选标记已用。评价保留 motivation 及正反标签，但没有“结束/是否重提”的候选级判断。已有 `FORECAST` 的 shouldSend=false 与 responseMode=wait，是已实现的晚期等待动作，不能说完全没有；它发生于选定候选之后，未给每条想法独立的“等待什么事件”或“何时失效”。#4 的 10 秒触发和沉默加权是其示例经验参数，不是 QQ 群适用阈值或保证。
2. #27/#28：当前 `tick` 在群作息、冷却、配额、未回应消息等初筛之后，只要停顿足够，主动话题概率可上升；随后还有 EVALUATE、发送预测与最终闸门，故不等于“安静就必发”。但初筛未将“合宜结束/仍可接续/适合开新话题”结构化；停顿越久的概率增长可能把合宜安静转为更多尝试。#27/#28 是面对面／自然互动观察，提示区分安静的互动意义，不给 QQ 秒数或因果效果。#29 进一步提醒异步文本的未回复不等于面对面 lapse。
3. #23/#26：当前 FORM 有历史和可能的外部内容，但没有当前共享对象的显式优先级与可见性核验；`topic_delivery` 以 response.replyTo、学习锚点、文本相似度依次寻找历史锚。把语义类似旧消息当当前可共享话题的做法有风险。12:03 的旧汉堡话题可能是这类风险，也可能是无锚点后以 thought.created 代替话题年龄；无日志不能给历史实际分支定因。#23 是双人 setting talk，#26 是视频家人互动；移用到 QQ 只是一项待验证设计假设：当前群消息/当前可见图片或链接比久远共同经历更容易形成共享起点。
4. #24/#25：FORM 仅区分 system1/2，不标记“提议一次话题”与“对未展开话题继续追问”。ARTICULATE 可问问题，FORECAST 有 ask/wait，priorExpectation 明确不能因没回复就催促；这是部分保护，但无逐话题的 nomination/pursuit 状态。#24/#25 正文未取得，索引只能支持把两种行动拆开作为设计选项，不能据此推断“多问更好”。
5. #28：当前 `trigger=topic` 代表一次主动尝试，而不是结束/继续旧话题/开启新话题的三选一。候选可能来自历史、记忆或外部资料，选择器仅看评分概率，最终闸门才试图定位旧话题。因此不是纯随机换题，但没有显式三分决策。#31 可启发“刚才在聊什么”的有证据简述；不应自动对所有沉默或所有新人插话。

## 二、修订方案与顺序

A. 立即保护：不再用新想法的 `created` 证明旧话题是 Recent。没有可信归属时区分 `new_topic_with_source`、`continuation_with_anchor`、`historical_revisit`、`unknown`。主动 `unknown` 默认不发；真正新话题需当前可见群内容或审过的外部来源等可核验起点。保留常规直接回复行为。若要允许无来源的自由闲聊，需产品裁决其限定条件。这是短期防 12:03 类错误的独立保护，不需要先完成整个稳定身份系统。
B. 稳定身份：沿前一份话题身份规划，先建稳定话题 ID/群内归属及最后活动时间；利用 R 的 resolved 同群引用边延长话题，unknown/unresolved/ambiguous 不作证明。保留 `Stage::Closing/NaturalEnd` 和既有三级阈值，不建第二套状态机。`thoughts.created` 只代表想法创建，不代表话题最近活动。
C. 生成：将“当前共享对象/现谈话/有证据未了事项/外部新内容”作为有限来源类型提供给 FORM；生成的每条候选必须关联来源 ID 或显式 unknown。可提出结束、接续、开启三种行动，允许空数组。模型输出的来源由宿主验证；不照搬 #4 的嵌入相似度阈值。候选多样性按话题/行动/来源检查，避免三条同义旧题。
D. 选择：EVALUATE 每条候选增加行动类型、所指话题、结束信号、重提理由与证据。模型可以判断语用合宜，但宿主计算话题年龄、状态与可引用目标。先过滤不能投递的候选，再保持一次概率抽签；候选被拒时可在同池合法候选间选，不重抽多次。最终 ARTICULATE 后继续复核，防文案偏离。高动机不豁免硬约束。
E. 等待与停顿：把 wait 作为整轮合法结果，也记录逐候选的“因何等待、等待什么新消息、有效期”。停顿只触发一次考虑机会，不承诺发言。选择前显式区分结束/接续/新起；对结束态可以不做任何事。初次开口与再次追问分别判定；无人回应只记弱信号，不能自动催促。
F. 可见性与控制：当前共享对象必须确实存在于该群可见上下文；跨群、私聊或旧成员专属背景不得当本群共享对象。保留正常/暂停/停止参与及其可观察状态（#1/#5），角色、权限、可见性分别呈现（#3）。新成员场景可试验 #31 的一句有据概括，但不宣称提升接纳。
G. 学习启用：保持默认关闭。稳定身份与静默口径修正后，先离线重放验证群隔离与负反馈，再灰度开启；不能先为“活跃”打开反馈学习。

## 三、判据与验收

针对 12:03：固定时钟，群 G 的汉堡话题最后活动在 47 分钟前、结束态，当前有无关新消息；FORM 生成全新高分汉堡候选且不带可靠来源，模型甚至有“已聊过去”的候选级负面信号。断言绝不投递无引用汉堡消息；仅当同群唯一锚点存在，且有经核验的新增事实、未决请求或明确群友邀请，并通过必要性判定，才可重提；重提必引用所回应的协议消息 ID。模型自报 urgency/高 relevance 不单独算证据。找不到锚点、歧义、跨群、R 未解析均不可伪造 Recent。可选择同时存在的合法当前候选，但全轮只抽签一次。结构化日志记录候选 ID、来源、话题 ID、age/stage、等待或拒绝原因及最终发言类型。不能用旧事故归因替代这个确定性端到端测试。

其他验收：真正当前共享图片/链接的候选可进入评价但不保证发言；明确结束的停顿保持静默；首次提议未得到展开时，不因单次沉默自动追问；后续出现真实相关消息可重新评价留存想法；暂停/停止参与时无发言且状态可查询；群 A 的旧话题不得以群 B 内容为共享起点。实地评估分开记录“开始一次对话”“持续互相回应”“新人被接纳”，后者须成员反馈，不能用消息量代理。CA 文献只支持机制假设，不宣称这些指标一定改善。

## 四、未由文献决定的产品口径

1. 无可靠归属的主动闲聊默认沉默，还是在有限条件下允许无来源新起？建议默认沉默；若允许，应单独定义配额及可见性条件。
2. 第三层哪些“新证据/未决事项/明确邀请”足以重提？建议仅有可定位到当前群消息的证据；梗类放宽需群级反馈达到门槛，不能凭模型自评。
3. 未回应后是否允许一次 follow-up？建议默认不追问；若产品需要，需明确独立授权、时间窗与停止条件。
4. 是否对群内新成员提供 #31 式概括？建议仅在其明确加入当前互动且确有可公开的当下话题时考虑，需单独验收“接纳”，不以开口率代理。
