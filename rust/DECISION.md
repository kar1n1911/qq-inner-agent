# P6d 三层决策

配置 `agent.threeLayerDecision: true` 开启。省略或设为 `false` 时保留 JS 的
message/pause 调度、随机数消耗、模型 payload 与状态更新顺序；不会初始化新增路径所需的表。

`decision::screen` 返回两个独立阻断原因，`None` 表示通过：

- ①根据 pending、点名、静默、小时配额及冷却判断回复资格。通过后仍由原流水线使用消息、
  expectation 和 activity 上下文判断具体回应。
- ②根据群状态、上次自身发言、群级未使用且未过期的想法、主动配额/冷却与该群作息判断资格。
  不把 `!pending` 当成主动资格，也不受旧 `pause_done` 限制。复用 `media_select::group_activity`，
  包括其三天/二十条消息的作息冷启动门槛；活跃群、未处理消息或有效 expectation 都阻断②。
- 同时通过时优先①；②通过后才抽签。概率随沉默时间、距自身发言时间增长，最高 0.15。
  抽签后至少间隔 60 秒再尝试，同时保留已有 minThink、主动冷却、activity 块及并发限制。

集中初筛在 tick 中执行，在首次观察模型调用前再复核，以免异步调度期间的新消息绕过准入。
审计事件 `decision_screen` 分别记录两层阻断原因。想法池/群作息只约束②；没有新消息只阻断①。
③的 articulation、装饰与输出校验保持不变。主动尝试使用独立 assessment ID，消息处理游标仍指向真实消息。

本阶段对设计的具体化：概率使用保守的固定上限启发式，没有新增可学习概率参数；
§12 的完整话题生命周期分类不在本次接入范围，暂用冷清、足够沉默、消息已处理及无 expectation 作为保守准入条件。
新开关启用时由文字决策分支接管调度，旧 media 分支仍在开关关闭时维持原行为。

验证：`engine_parity` 保留真实 Node oracle 逐条对照，并新增 mock provider 零调用、
独立主动资格、回复优先、概率拒绝/触发及重试节奏测试；启发式断言区间和方向，不冻结精确概率。
